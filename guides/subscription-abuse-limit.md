# 订阅链接被滥用怎么办：设备数与 IP 限制

机场跑起来之后，最常见的一种“亏本”不是节点贵，而是订阅链接被滥用了：一个人买的套餐，十几台设备同时在线；或者链接被人转贴到公开群组，流量几天就被刷爆。发现得晚，整个月的带宽成本都替别人扛了。处理这类问题不能只靠封号，封得太狠会误伤正常用户，完全不管又会亏到关站。正确的做法是先分清滥用类型，再用设备数和 IP 限制把口子收紧，最后留好申诉通道。

## 先判断：到底是哪种滥用

看到流量异常先别急着封，先看三组数据：这个用户最近 24 小时的流量是不是远高于平时；同时在线的设备数是不是突然翻倍；登录 IP 是不是跨了多个城市、甚至多个国家。三种情况的处理方式完全不同。

第一种是正常使用波动：用户换了新手机、家里多了一台设备，或者出差换了网络，设备数和 IP 略有增加，流量曲线没有断崖式上涨。这种情况不用处理，顶多观察一天。

第二种是小范围分享：订阅被分享给家人或朋友，设备数长期稳定在五六台，IP 集中在两三个城市，流量比套餐均值高但不离谱。这是规则问题，不是攻击问题，靠限额就能解决。

第三种是公开倒卖或盗链：设备数在短时间内暴涨到十几台甚至几十台，IP 遍布各地，流量在几小时内冲掉大半个月的额度。这种情况要立刻止血，不能只靠调参数慢慢等。

```bash
# 先看面板和节点端的关键指标，再下结论
# 1. 该用户 24 小时流量、历史日均流量
# 2. 同时在线设备数、近 24 小时出现过的不同 IP 数
# 3. 流量突增的起始时间点：是慢慢涨上去的，还是某一刻突然爆发的
```

> 为什么要先分类型再动手？直接封号对第三种是对的，对第一种却是误伤。用户只是换了台手机就被封，第二天工单和退款就会找上门。先看数据，处理才有依据。

## 第一步：把设备数和 IP 上限立起来

设备数限制是最直接的一道闸：一个订阅同一时间最多允许几台设备在线，超了就拒绝新的连接。IP 限制是第二道闸：防止一个人用一台设备、换着 IP 池轮流刷，或者把链接挂到多地服务器上分发。两道闸要一起用，只限设备不限 IP，盗链者换 IP 就能绕过去；只限 IP 不限设备，一台设备开几十个连接也能把流量吃光。

落到面板设置上，建议按套餐分档，而不是全站一个数。普通套餐给 3 台设备、24 小时内不超过 5 个不同 IP；高阶套餐可以放宽到 5 台设备、10 个 IP。档位写进套餐说明里，购买前就讲清楚规则。

```yaml
# 限额思路示例（按你所用面板的实际字段填写）
# 普通套餐：同时在线设备不超过 3 台，24 小时不同 IP 不超过 5 个
# 高阶套餐：同时在线设备不超过 5 台，24 小时不同 IP 不超过 10 个
# 超限时的处理：拒绝新设备连接，老设备不受影响
# 注意：超限只拦新连接，不要把已在线的正常设备一并踢掉
```

> 为什么超限只拦新连接、不踢老设备？滥用者新加的设备连不上，滥用自然就停了；而正常用户正在用的设备不会突然断线，误伤面最小。把所有设备一并踢掉，连正常用户也一起得罪了。

## 第二步：对已泄露的链接做重置，而不是只改限额

如果订阅链接已经被贴到公开地方，光加限额是不够的：原链接还在别人手里，限额一松就会卷土重来。这时要给受影响的用户重置订阅链接，旧链接立即失效，新链接只发给用户本人。

重置之前先做两件事：一是确认这个用户本身是不是倒卖者，如果是倒卖，重置等于帮他换了一条新链接继续卖，应该直接封禁而不是重置；二是先备份一次数据库，批量操作前有备份才敢回滚。关于备份的具体步骤，可以对照本仓库的 [Xboard 数据库备份：MySQL 导出导入实操](xboard-mysql-backup.md) 先走一遍。

```bash
# 重置订阅链接的操作顺序（面板后台操作）
# 1. 在用户管理里确认该用户的设备数、IP 数和流量曲线
# 2. 判断是正常用户被盗链（重置），还是主动倒卖（封禁）
# 3. 为正常用户生成新订阅链接，旧链接立即失效
# 4. 通过站内消息或注册邮箱把新链接发给用户本人，并提醒不要公开转发
```

> 为什么重置后要专门提醒“不要公开转发”？很多泄露不是恶意的，是用户把链接截图发到群里求助，或者发给朋友时没意识到链接等于账号密码。不说清楚，新链接过几天又会出现在同一个群里。

## 第三步：分级处理，别一上来就永久封号

滥用处理建议分三档，档位越往上越重。第一档是触发限额：新设备连不上，小范围分享到这一步就停了。第二档是临时限制：确认分享或轻微倒卖时，先限速或暂停订阅 24 小时，并站内通知原因和恢复时间。第三档是永久封禁：只留给证据确凿的倒卖、盗链，或屡犯的用户。

```bash
# 分级处理清单
# 第一档：触发设备/IP 上限 -> 拒绝新连接，站内提示超限原因
# 第二档：确认分享或轻微倒卖 -> 限速或暂停 24 小时，通知原因与恢复时间
# 第三档：证据确凿的倒卖或屡犯 -> 封禁账号，订阅链接作废，不再重置
```

> 为什么要分级而不是一次封死？机场的用户关系是长期订阅关系，误封一个正常用户的代价远高于放过一次轻微分享。分级处理既拦住了滥用，也给正常用户留了“我只是不小心”的台阶，工单量会少很多。

## 验证：限额生效了没有

改完设置不要凭感觉，要拿一个测试账号实测一遍。用测试账号模拟超限：先连满设备数，再加一台，看新设备是不是被拒绝；换几个 IP 登录，看 IP 计数是不是正常累加；触发限额后，原有设备是不是还能正常使用。

```bash
# 验证清单（用测试账号做，不要拿真实用户账号试）
# 1. 设备数连满上限后，新设备连接应被拒绝，并有明确的超限提示
# 2. 换 IP 登录后，24 小时不同 IP 计数应正常增加
# 3. 触发限额后，已在线的设备不应被踢下线
# 4. 重置订阅链接后，旧链接应立即失效，新链接可正常拉取订阅
```

> 为什么必须用测试账号验证？直接拿真实用户账号试，万一规则配错，真实用户当场断线，验证就变成了事故。测试账号测通了，再推给全站。

## 常见坑汇总

- **全站一个限额、不分套餐**：高阶用户花了更多钱却和普通用户一样的设备数，续费意愿会被直接打掉，限额一定要跟套餐档位挂钩。
- **只限设备不限 IP**：盗链者换 IP 池轮流连，设备数看起来正常，流量照样被刷爆，两道闸必须一起上。
- **超限就踢掉所有设备**：正常用户正在用的设备也被踢下线，误伤面最大，正确做法是只拒绝新连接。
- **只改限额、不重置已泄露链接**：旧链接还在公开群组里流传，限额一松就复发，泄露的链接必须作废重发。
- **分不清被盗链和主动倒卖**：给倒卖者重置链接等于帮他续命，重置前先看数据判断用户本身有没有问题。
- **封了不通知**：用户不知道为什么被封，只会认为是跑路，站内通知原因、恢复时间和申诉方式，工单量至少少一半。
- **没有申诉通道**：家庭共用、换设备、出差换网都可能触发限额，没有申诉通道，误伤的用户只能流失，留一个工单入口成本很低。
- **规则事后才公布**：购买时没写设备数和 IP 上限，事后执行就是“临时改规则”，限额档位要写进套餐说明里。

设备数和 IP 限制本身不复杂，难的是分寸：限额太松等于没设，太严又会误伤正常用户。按套餐分档、两道闸一起上、泄露链接及时重置、处理分级留申诉通道，这四件事做到位，绝大多数订阅滥用都能在不伤口碑的前提下压下去。
