# 机场搭建总览：自建一个机场需要准备什么

很多人以为搭机场就是「买台服务器装个脚本」，真动手才发现它是一串组件：面板管用户和订阅，节点端负责转发流量，域名和证书决定订阅能不能正常拉取。这篇先把整体结构讲清，后面每一篇再拆开讲一个组件怎么装、怎么调。

## 一、整体结构

先理清各部分的关系：

- 用户在客户端（Clash Verge、Shadowrocket 等）里导入订阅链接
- 订阅链接由面板生成，面板（如 Xboard）负责管理用户、套餐、流量统计和节点列表
- 节点端（如 V2bX）跑在各台落地 / 中转服务器上，从面板拉取配置，按协议（VLESS、Hysteria2 等）转发流量
- 流量路径可以是「用户 → 落地机」直连，也可以是「用户 → 中转机 → 落地机」

## 二、需要准备的东西

1. **一台面板机**：跑面板和数据库，配置不用高，1 核 1G 就够起步，它本身不承载用户流量。
2. **一台或多台节点机（落地）**：真正转发流量的服务器，带宽和线路质量决定用户体验，是成本大头。
3. **一个域名**：面板和订阅都要用域名，DNS 托管到 Cloudflare 方便管理。
4. **（可选）中转机**：做入口转发，改善晚高峰的连接速度和稳定性。

## 三、软件选型（本系列教程的默认组合）

- 面板：Xboard（界面现代，Docker 部署省事）
- 节点端：V2bX（对接 Xboard，支持 VLESS / Hysteria2 / Trojan 等协议）
- 反代与证书：Caddy 或 Nginx，证书用 Let's Encrypt 自动续期
- 数据库 / 缓存：MySQL + Redis（随 Docker Compose 一并拉起）

## 四、搭建顺序

1. 域名解析与 Cloudflare 基础设置
2. 面板机部署 Xboard（Docker Compose）
3. 落地机安装 V2bX 并对接面板
4. 在面板里添加节点（先从 VLESS Reality 开始），生成订阅
5. 客户端导入订阅并测试连通性
6. 进阶：加中转、换落地、做节点分组和倍率

后面的每一篇对应其中一步，照着顺序做就能跑通。

## 五、先想清楚的三个问题

- **自用还是对外运营**：自用可以跳过支付对接和用户管理；对外运营要把套餐、支付、客服都算进工作量。
- **预算**：起步一台面板机 + 一台落地机即可，每月成本主要在落地机的带宽上，先小后大。
- **维护时间**：节点被封、证书过期、订阅异常都是日常，自建意味着这些都要自己处理。
