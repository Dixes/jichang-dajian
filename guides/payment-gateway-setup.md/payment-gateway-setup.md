# 面板对接支付：易支付与套餐定价

机场要持续运营就必须解决收款：用户付钱、系统自动开通，这个链路跑通了才算真正的「机场」，而不是手动拉人的小作坊。本文讲 Xboard 对接易支付的完整流程，以及套餐定价的设计思路。

## 准备工作

注册一个易支付商户账号，拿到商户 ID、商户密钥和支付网关地址。易支付支持微信、支付宝等多种收款方式，费率通常在 1%-3%。准备一个测试账号用于走完整支付流程，千万别直接拿真实用户当小白鼠。

确认面板的支付回调地址能被外网访问：

```bash
curl -s -o /dev/null -w "%{http_code}" https://panel.example.com/api/v1/guest/payment/notify
```

回调不通会导致「用户付了钱、系统没开通」，这是最伤口碑的故障，务必先验证。

## 对接易支付

登录 Xboard 后台 → 商店设置 → 支付网关，新增易支付通道，填写：

```
网关名称：易支付
商户 ID：10001（示例，填你自己的）
商户密钥：你的密钥
网关地址：https://pay.example.com/submit.php
回调地址：https://panel.example.com/api/v1/guest/payment/notify
```

商户密钥的作用是签名校验，防止伪造回调。填完后保存，支付网关列表里启用该通道。注意密钥不要截图发到公开群里，泄露后立即在易支付后台重置。

## 套餐定价设计

定价要覆盖三部分成本：服务器 + 带宽成本、支付通道费率、你的运维时间。参考模型：

```
月付 ¥10：100GB 流量，基础分组，适合轻度用户
季付 ¥25：300GB 流量，标准分组，折合约 8.3 折
年付 ¥90：1200GB 流量，全部分组，锁定长期用户
```

定价技巧：设置一个明显划算的长期套餐引导年付，现金流更稳定；入门套餐价格要低，降低尝试门槛；流量不要给「无限」，无限套餐必然被滥用。用倍率（见分组与倍率篇）调节不同节点的实际成本。

在 Xboard 后台 → 商店 → 套餐管理，按上面的模型新建套餐，绑定支付网关、设置流量、有效期和可见分组。

## 验证

1. 用测试账号下单一个最低价套餐，走完真实支付（1 分钱测试或易支付的测试模式）
2. 检查支付成功后账号是否自动开通、流量是否到账
3. 在易支付后台核对订单金额与面板订单是否一致
4. 测试退款/掉单场景：支付成功但回调超时的订单，能否在后台手动补单

```bash
# 检查面板订单状态
curl -s "https://panel.example.com/api/v1/admin/orders" -H "Authorization: Bearer 管理员token" | head -c 500
```

重点验证「掉单」处理流程，这是支付对接中最常见的线上故障。

## 常见坑

一是回调地址填错或被防火墙拦，用户付款后不到账，客服被冲。二是商户密钥前后多复制了空格，签名永远对不上，支付一直失败。三是定价不算成本，卖得越多亏得越多，先算清单位流量成本再定价。四是只接一种支付方式，用户付不了款就流失，至少覆盖微信和支付宝。

## 不想自己搭？
