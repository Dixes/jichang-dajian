# V2bX 更新后节点全部离线：版本回滚与兼容排查

更新前所有节点都在线，执行一次 V2bX 更新、重启服务，面板上的节点却一个接一个变离线，订阅也跟着拉不到节点。这种「更新即掉线」的问题，十有八九不是面板挂了，也不是机房网络出了问题，而是新版本和旧配置、旧面板版本不兼容。处理顺序很重要：先定性、再回滚验证，最后才考虑升级适配，不要一上来就重装节点端，更不要同时改面板、改配置、改版本——同时动三处，修好了也不知道是哪一步起的作用。

## 先定性：是更新引起的，还是凑巧同时出问题

更新后掉线，先确认两件事：掉线的时间点是不是和更新时间对得上，以及是不是所有节点同时掉线。

```bash
# 看 V2bX 服务最近的启动和报错记录，确认掉线是不是从更新重启后开始的
journalctl -u v2bx -n 200 --no-pager | grep -iE 'error|fail|panic|version|incompatible'

# 看服务当前状态：是没跑起来，还是跑着但连不上面板
systemctl status v2bx --no-pager
```

如果只有个别节点掉线、其他节点正常，那大概率不是版本问题，而是个别节点的网络、防火墙或配置问题，可以先对照本仓库的另一篇教程按离线排查：[V2bX 对接失败：面板显示节点离线怎么办](guides/v2bx-offline-troubleshoot.md)。如果所有节点在同一时间段内一起掉线，而且时间点正好卡在更新重启之后，再按本篇往下走：先回滚，再谈适配。

还有一种情况要先排除：更新过程中服务根本没有成功重启。上面 `systemctl status` 如果显示 failed、activating 循环重启，问题可能出在更新包下载不完整、文件权限被改坏，而不是版本兼容。先看日志里有没有文件缺失、权限拒绝这类报错，有的话先把更新步骤重做一遍，确认安装脚本完整执行完再谈回滚。

## 第一步：回滚前先备份，别把旧配置也丢了

回滚本身不难，难的是回滚之后发现旧配置也被新版本改写过，想回都回不去。动手之前，先把当前配置文件和版本信息备份一份：

```bash
# 备份当前配置文件和版本信息，备份文件带日期，方便事后对照
cp /etc/V2bX/config.json /etc/V2bX/config.json.bak-rollback
/etc/V2bX/V2bX --version 2>/dev/null || v2bx --version 2>/dev/null
ls -la /etc/V2bX/
```

备份时顺手记下两个版本号：更新前能正常跑的旧版本号（如果还能从更新日志、安装记录里找到），以及现在出问题的当前版本号。回滚的目标就是回到旧版本号，而不是「随便装一个更老的版本」。如果旧版本号实在找不到，至少要记下更新前后的时间点，方便对照更新日志里的变更说明。

另外提醒一句：回滚期间不要顺手改面板配置、换节点密钥、调防火墙。回滚验证的前提是「只动版本这一个变量」，其他条件保持不变，这样回滚后节点恢复在线，才能确定问题确实出在版本上。

## 第二步：从日志里确认是不是兼容问题

回滚之前花五分钟看日志，确认报错指向版本或配置兼容，而不是密钥、网络这类老问题。常见的兼容类报错包括：配置文件字段未知、字段类型变了、协议核心版本对不上、面板接口返回了节点端不认识的字段。

```bash
# 重点找 unknown field、deprecated、unsupported、version、parse 这类关键字
journalctl -u v2bx -n 300 --no-pager | grep -iE 'unknown|deprecated|unsupported|version|parse|unmarshal'

# 如果 V2bX 有单独的运行日志文件，也可以直接翻最近的报错段
tail -n 200 /var/log/V2bX.log 2>/dev/null | grep -iE 'error|fail'
```

日志里如果出现「未知字段」「不支持的配置项」这类报错，说明新版本改了配置格式，旧配置文件里有它不认识的字段，或者新版本要求新增某个字段而旧配置里没有。这时候不要直接删字段、也不要凭感觉补字段——先回滚恢复服务，再到第三步之后对照变更说明处理。

如果日志里没有兼容类报错，只有连接超时、认证失败，那问题可能不在版本上：先按密钥、地址、防火墙的老排查顺序走一遍，不要为了回滚而回滚。回滚能解决的是版本问题，解决不了密钥错、端口被封这类问题。

## 第三步：回滚到更新前的版本并验证恢复

确认方向后开始回滚。具体回滚命令取决于你当初的安装方式：用官方安装脚本装的，一般可以指定版本重装；用包管理器或手动下载二进制装的，就把旧版本二进制换回来。下面给出通用的思路，命令里的版本号换成你自己的旧版本号：

```bash
# 停止当前出问题的服务，避免新旧进程同时跑
systemctl stop v2bx

# 按你当初的安装方式，装回旧版本号（示例为指定版本的思路，版本号换成自己的）
# 如果是安装脚本支持版本参数，就用版本参数重装；如果是二进制安装，就把旧二进制放回原路径
# 安装完成后务必确认版本号确实变回去了，不要凭感觉认为装好了
/etc/V2bX/V2bX --version 2>/dev/null || v2bx --version 2>/dev/null

# 恢复回滚前备份的配置文件（如果新版本改写过配置文件）
cp /etc/V2bX/config.json.bak-rollback /etc/V2bX/config.json

# 重启服务并看状态和日志
systemctl restart v2bx
systemctl status v2bx --no-pager
journalctl -u v2bx -n 100 --no-pager | tail -50
```

回滚后验证分三步，缺一不可：服务状态是 active、日志里不再刷兼容报错、面板后台节点状态变回在线。三项都满足，才算回滚成功；如果服务起来了但面板还是离线，说明除了版本之外还有别的问题，要回到密钥、面板地址、防火墙的排查上，而不是继续换版本。

回滚成功后，先让服务稳定跑一段时间，不要立刻再次更新。把「旧版本号能跑、新版本号掉线」这个结论和日志报错截图或文本保存下来，后面做升级适配、向面板方或节点端反馈时，这些都是关键证据。

## 第四步：要升级的话，先弄清新版本到底改了什么

回滚只是恢复服务，不是最终答案。如果确实需要新版本的功能或安全修复，升级前要先做三件事，缺一件都不要直接在生产节点上升级：

1. **读变更说明**：找到新版本的更新日志或发布说明，重点看有没有「破坏性变更」「配置格式变更」「最低面板版本要求」这类字眼。有最低面板版本要求的，要先确认自己的面板版本够不够，不够就先升级面板，或者暂缓升级节点端。
2. **核对配置字段**：把新版本的配置示例和自己的旧配置文件逐项对照，重点看新增字段、改名字段、改类型的字段。新增必填字段要在升级前补好，改名字段要按新名字改，不要新旧字段混着写。
3. **先在单台节点上试**：不要所有节点一起升。先挑一台影响最小的节点升级，观察一小时，确认在线、流量上报、订阅拉取都正常，再分批升其他节点。单台出问题，回滚也只影响一台。

```bash
# 升级前在单台节点上先做一次配置备份，升级后立刻验证
cp /etc/V2bX/config.json /etc/V2bX/config.json.bak-upgrade
systemctl status v2bx --no-pager
journalctl -u v2bx -n 50 --no-pager | tail -30
```

分批升级还有一个好处：万一新版本有问题，你能立刻看出来是「这一批升出的问题」，而不是所有节点同时掉线、手忙脚乱。一次全量升级、一次全量掉线，是机场运维里最不应该出现的操作。

## 第五步：升级后逐项验证，别只看面板在线

升级完成后，不要只看面板上节点变绿就收工，按下面四项逐项验证：

```bash
# 1. 服务状态正常，没有循环重启
systemctl status v2bx --no-pager

# 2. 日志里没有持续的报错
journalctl -u v2bx -n 100 --no-pager | grep -iE 'error|fail'

# 3. 用测试订阅链接拉取一次，确认该节点出现在订阅里
curl -s https://panel.example.com/api/v1/client/subscribe?token=YOUR_TOKEN | head -c 500

# 4. 等一个流量上报周期，确认面板里的流量统计在正常增长
```

上面订阅地址里的域名和 token 都是占位符，换成你自己的面板域名和测试 token。面板在线只是第一步，订阅能拉到、流量能上报、日志保持安静，才算升级真正完成。任何一项不满足，都先停在这一台节点上排查，不要继续往下一批推。

## 常见坑

- **所有节点一起升级**：一出台问题就是全站掉线，永远先单台灰度、分批推进。
- **回滚时不备份配置**：新版本改写过配置文件，回滚后旧配置找不回来，只能重建节点。
- **回滚后不确认版本号**：以为装回去了，其实还是新版本在跑，报错依旧，误以为回滚无效。
- **同时改版本又改配置**：修好了也不知道是哪一步起的作用，出问题也分不清责任在谁。
- **不看变更说明直接升**：新版本要求面板版本、配置字段都变了，旧环境直接升必然掉线。
- **只看面板在线就收工**：订阅拉不到、流量不上报，都是面板在线掩盖下的问题，要逐项验证。
- **回滚成功就再也不升级**：旧版本迟早会遇到安全修复和协议适配问题，回滚后要留出时间做有准备的升级，而不是一直拖着。
