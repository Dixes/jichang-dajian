# 订阅安全：防泄露与链接重置

订阅链接是机场的命脉：它包含了用户全部节点信息，一旦泄露，任何人都能白嫖流量，严重的会被拿去倒卖或攻击节点。订阅安全的核心就两件事——降低泄露概率、泄露后快速止损。本文讲 Xboard 的订阅安全配置和链接重置流程。

## 准备工作

理解订阅链接的结构：通常是 `https://panel.example.com/api/v1/client/subscribe?token=xxx`，token 与用户账号绑定。拿到链接就等于拿到该用户的所有节点和账号凭证，所以必须当密码一样保护。

检查面板后台是否开启了以下基础项：用户中心展示订阅链接时是否有「复制链接」之外的「重置链接」按钮，管理员能否在用户详情页手动重置。

## 防泄露：从源头减少风险

第一，教育用户不要分享订阅链接。在用户中心的公告或 FAQ 里明确写：分享订阅链接等同于分享账号，一经发现封号处理。技术手段只能兜底，用户意识是第一道防线。

第二，开启订阅链接的访问控制。Xboard 支持按 UA 或请求频率限制订阅接口：

```nginx
# 在反代层限制订阅接口频率
limit_req_zone $binary_remote_addr zone=sub:10m rate=5r/m;
location /api/v1/client/subscribe {
    limit_req zone=sub burst=3 noreject;
    proxy_pass http://127.0.0.1:3000;
}
```

`5r/m` 表示每分钟最多 5 次订阅请求，正常用户更新订阅远低于这个频率，而爬链接的脚本会被挡住。频率限制放在反代层做，不占用面板资源。

第三，定期轮换订阅域名或路径前缀。即使链接泄露，攻击者拿到的也是旧域名的链接，配合下面讲的重置机制，泄露窗口可以压到很小。

## 链接重置：泄露后的止损流程

发现某用户流量异常（例如 100GB 套餐一天跑完），按以下流程处理：

1. 在 Xboard 后台找到该用户，进入详情页
2. 点击「重置订阅链接」/「重置 UUID」，生成新的 token
3. 旧链接立即失效，泄露出去的链接变成死链
4. 通知用户重新复制新链接更新订阅

```bash
# 批量检查可疑用户：单日流量 Top 20
# 在面板数据库或后台统计页查看，示例为思路
echo "登录 Xboard 后台 → 用户管理 → 按今日流量排序"
```

重置是原子操作，旧 token 立刻失效，不用担心「新旧链接同时有效」的窗口。对于确认倒卖订阅的账号，直接封禁并重置，不要只重置不封号。

## 验证

- 用测试账号复制订阅链接，浏览器无痕模式打开，确认能正常返回节点
- 在后台重置该测试账号链接，旧链接再次访问应返回 401 或空内容
- 压测订阅接口：`ab -n 50 -c 5` 打订阅 URL，确认超频请求被限流
- 检查重置后用户端的订阅是否需要手动更新（通常需要，提前在公告里说明）

## 常见坑

一是从不看流量统计，泄露几个月才发现，定期看 Top 用户流量是基本功。二是重置链接后不通知用户，用户还以为机场跑路，客服工单爆炸。三是把订阅链接和面板登录密码设成一样，一个泄露全泄露。四是认为 HTTPS 就够了，HTTPS 只防传输窃听，防不住用户主动分享。
