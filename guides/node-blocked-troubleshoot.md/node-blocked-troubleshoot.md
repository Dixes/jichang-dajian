# 节点被封排查与换 IP 流程

节点突然连不上，先别慌着换机器：一半的「被封」其实是配置、证书或防火墙问题。按这篇的排查顺序走，10 分钟定位原因，真被封了再按流程换 IP，把损失降到最小。

## 准备工作

先确认问题范围：是单个节点挂了，还是所有节点都挂了？

```bash
# 服务端：服务是否存活
systemctl status sing-box
ss -tlnp | grep 443
# 本地：ping 与端口测试
ping -c 3 node.example.com
telnet node.example.com 443
```

如果 ping 不通、端口不通，可能是 IP 层面的问题；如果端口通但连不上，多半是配置或证书问题。先分清再动手。

## 排查步骤

按顺序排查，别跳步：

```bash
# 1. 服务端日志看报错
journalctl -u sing-box --since '30 min ago' -p err
# 2. 证书是否过期
openssl x509 -in /etc/letsencrypt/live/node.example.com/cert.pem -noout -dates
# 3. 防火墙规则是否被改
iptables -L -n | head -20
# 4. 域名解析是否正常
nslookup node.example.com
```

证书过期是最常见的「假被封」：Let's Encrypt 90 天有效期，自动续期失败又没人看，节点就悄悄挂了。域名被污染或解析到错误 IP 也会表现为连不上，换个 DNS（如 8.8.8.8）测试确认。

如果以上都正常，但从国内就是连不上、而境外测试正常，基本可以判定 IP 或端口被封。

## 换 IP 流程

确认被封后，按这个流程换：

```bash
# 1. 商家后台更换 IP（或重建实例）
curl -s ifconfig.me  # 记录新 IP
# 2. 更新 DNS 解析到新 IP
# 3. 面板更新节点地址
# 4. 如用了 CDN，确认源站 IP 已更新
```

关键细节：换 IP 后旧 IP 上的服务不用急着删，保留几天观察；DNS TTL 提前设短（如 300 秒），换 IP 时生效快；面板节点地址改完后提醒用户更新订阅。

如果商家不支持换 IP，只能重建实例：先备份配置（参考备份迁移篇），新机器部署好、测试通过后再切 DNS，把 downtime 压到最低。

## 验证

```bash
# 新 IP 连通性
ping -c 3 新IP
# 端口测试
telnet 新IP 443
# 实际连接测试
# 用测试账号走新节点确认可用
```

确认新节点可用后，在面板把旧节点下线或删除，避免用户连到已死的节点。

## 常见坑

一是没排查就换 IP，结果是证书过期，换完照样挂。二是换了 IP 忘了更新面板节点地址，用户还在连旧 IP。三是 DNS 缓存，TTL 设太长导致切换慢。四是频繁被封还用同一家同一机房，换个商家或地区从根上降低概率。五是把被封 IP 的机器直接销毁，日志没留，连被封原因都复盘不了。
