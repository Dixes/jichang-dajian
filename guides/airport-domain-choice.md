# 机场域名怎么选：后缀、长度与解析商

搭机场的时候，域名往往是最后才想起来的东西：面板装好了、节点跑起来了，才发现还没决定用哪个域名，于是随手注册一个最便宜的，或者直接拿 IP 裸奔。等到用户多起来再想换域名，面板地址、节点地址、订阅链接、证书全都要跟着动，迁移成本比一开始选好大得多。域名这个东西，选的时候多花半小时，能省下以后好几天的折腾。

本文默认的场景是：你已经有面板和节点端的部署计划，正在给机场挑一个长期使用的主域名，并规划面板、节点、订阅分别用什么子域名。本文不讲面板和节点端的安装，安装部分看本仓库的其他教程。

## 先定结构：一个域名要拆成几部分用

不要把所有东西都挂在同一个域名上。面板、节点、订阅三者的用途不同，出问题的影响范围也不同，分开之后，某一处出问题时，改动可以只局限在那一处：

- **面板域名**：比如 `panel.example.com`，只给管理员和用户登录面板用，平时访问量不大，但安全性要求最高。
- **节点域名**：比如 `node-01.example.com`、`node-02.example.com`，给协议服务端用，是用户实际连接的地址，换节点、换 IP 时只动这里。
- **订阅域名**：比如 `sub.example.com`，只负责下发订阅链接，建议和面板域名分开，这样订阅链接被滥用、被频繁请求时，不会直接冲击面板。

> 为什么要这样拆？因为机场运营中最常见的操作就是换节点、换 IP、换订阅地址。如果三个功能挤在同一个域名上，任何一次改动都要动全身；拆开之后，换节点只改节点子域名的解析，面板和订阅都不受影响，出错面小得多。

域名数量上也别贪多：主域名一个就够了，上面这些子域名都从它派生。再注册一堆备用域名平时用不上，续费和管理成本反而一年比一年高。备用域名可以等主域名真的出问题、或者业务量大到需要分流时再加。

## 后缀怎么选：先看续费价，再看口碑

选后缀时，新人最容易犯的错误是只看首年注册价。很多后缀首年只要几块钱，续费却要几十甚至上百元，机场是要长期续费的，算账要按续费价算：

```bash
# 注册前先查一下这个后缀的续费行情，别只看促销价
# 顺带查一下你想要的域名有没有被注册
whois example.com
# 输出里看 Expiry Date（到期日）和 Registrar（注册商）
# 如果已被注册，whois 里通常能看到到期时间，有时等过期释放也是一条路，但别指望
```

选后缀的几条实用原则：

- **优先主流后缀**：`.com`、`.net` 是最稳妥的选择，解析、证书、各类服务对它们的支持都没有死角，用户也最容易记住和输入。
- **便宜后缀要算总账**：`.xyz`、`.top`、`.site` 这类后缀首年便宜，但要看续费价和转移政策。有些便宜后缀因为被滥用得多，个别场景下会受到更严格的审查，遇到问题时申诉和处理也更麻烦。
- **别用含义奇怪的后缀**：后缀本身就是品牌的一部分，一个让人读不出意思、或者容易和别的词混淆的后缀，用户记不住，口头传播也困难。
- **国别后缀要想清楚**：`.cn`、`.us` 这类国别后缀往往有额外的实名或资质要求，管理规则也和通用后缀不一样，除非你明确需要，否则没必要给自己加一道手续。
- **一次注册多年要谨慎**：对刚起步的机场，先按一年续费走，确认这个域名确实长期用得下去，再考虑一次续多年拿折扣。域名和业务方向绑定后想换，成本远高于那点折扣。

> 为什么续费价比首年价重要？因为域名一旦用起来，面板、节点、订阅、证书全都绑在上面，续费涨价你也得续，中途换域名的迁移成本远高于每年多出的那点续费。首年便宜、续费昂贵的后缀，长期算下来往往并不便宜。

## 长度与可读性：短、好念、不产生歧义

域名是每天都要被用户输入和传播的东西，选的时候按这几条过一遍：

- **越短越好，但别牺牲可读性**：十个字符以内、能一眼读出来的名字，比一串毫无意义的短字符更好记。用户记不住的域名，传播全靠复制链接，口碑传播就断了。
- **能念出来**：一个域名如果没法顺口念出来，用户向朋友推荐时就说不清楚。选好后自己念三遍，拗口的直接放弃。
- **避开容易混淆的字符**：`l` 和 `1`、`o` 和 `0` 混在一起的组合，用户手打时极容易输错，输错一次就是一次“连不上”的投诉。
- **少用连字符**：连字符在口头传播时最难说清楚，“某某杠某某”说两遍对方也未必能拼对。非用不可时，最多一个，而且要放在不容易被忽略的位置。
- **别蹭别人的品牌词**：和知名品牌、知名站点高度相似的域名，短期看能蹭到一点流量，长期看是麻烦的来源，争议和投诉处理起来远比注册费贵。

注册之前，先把候选域名放到几个地方验一下：

```bash
# 查解析现状：这个域名现在有没有解析记录、指向哪里
dig +short example.com
dig +short panel.example.com

# 查历史：如果这个域名以前被别人用过，顺带看一下它以前的解析和用途
# 有公开历史记录工具可以查，重点看它以前有没有被用于不良用途
# 有不良历史的域名，接手后可能要花额外时间洗掉旧印象，不如换一个干净的
```

## 注册商与解析商：分开看，别图省事

注册商管的是域名的所有权，解析商管的是域名解析到哪里。很多人图省事，注册和解析都在同一家做，其实两者可以分开选，各取所长：

**注册商看这几点：**

- **支持域名隐私保护**：注册信息默认公开时，你的姓名、邮箱、电话都可能被查到，隐私保护能把这些信息隐藏起来，对个人运营者尤其重要。
- **支持双因素登录**：域名账号一旦被盗，整个机场的域名都可能被改解析，账号安全就是业务安全，双因素是底线。
- **转移政策宽松**：好的注册商不会用各种手续卡住你的转出，转移码能顺利拿到，万一要换注册商时不被刁难。
- **续费提醒到位**：域名过期是机场运营里最低级、也最致命的事故，注册商的到期提醒、自动续费选项都要提前确认好。

**解析商看这几点：**

- **解析生效速度**：解析商的全球节点分布和 TTL 支持，决定了你改一次解析后，用户要等多久才能用上新地址。换节点、换 IP 这种高频操作，解析生效慢会直接拖长故障时间。
- **TTL 设置灵活**：TTL 是解析记录的缓存时间，设得太长，改解析后用户要等很久才生效；设得太短，每次查询都回源，解析商的压力和故障面都会变大。平时可以设 300 秒到 600 秒，计划内的大改动前，提前一天把 TTL 调低，改完后再调回去。
- **支持 API 操作**：节点多起来之后，手动在网页上改解析又慢又容易错，支持 API 的解析商可以让解析变更写进脚本，和面板、节点端的运维流程接起来。
- **有状态监控和告警**：解析商出问题时，你要第一时间知道，而不是等用户反馈。解析商自带监控和告警，或者你自己用外部监控盯着解析结果，都是必要的。

```bash
# 换解析商或改解析后，用不同解析器各查一次，确认全球生效情况
dig +short @8.8.8.8 node-01.example.com
dig +short @1.1.1.1 node-01.example.com
dig +short @223.5.5.5 node-01.example.com
# 三次结果一致，才算改动真正生效；不一致时先看 TTL 剩多久，别急着反复改
```

> 为什么要分开看注册商和解析商？因为两者出问题的影响不一样：注册商出问题是所有权风险，解析商出问题是可用性风险。分开选的好处是，一边出问题时，另一边不受牵连，你还有腾挪的空间。全部押在同一家，等于把两种风险绑在了一起。

## 证书规划：域名定了，证书才好申请

域名结构定下来之后，证书的申请方式也就定了。节点和面板都要用 HTTPS，证书覆盖范围要和子域名规划对上：

- **单域名证书**：只覆盖一个子域名，适合只有一个面板域名、且节点用 IP 或其他方式的极简场景。
- **通配符证书**：一张证书覆盖 `*.example.com` 下的所有子域名，节点加到十个、二十个都不用重新申请，适合子域名多的机场。
- **申请方式**：通配符证书通常要用 DNS-01 验证，也就是在解析商那里加一条 TXT 记录来证明你拥有这个域名。选解析商时，顺带确认它支持 API 添加 TXT 记录，否则每次续期都要手动操作，迟早会漏掉一次。

```bash
# 以 acme.sh + DNS API 为例，申请通配符证书的思路
# 具体变量名按你所用解析商的 API 文档来，不要照抄
export DP_Id="你的解析商 API ID"
export DP_Key="你的解析商 API Key"
acme.sh --issue --dns dns_dp -d example.com -d "*.example.com"
# 证书到期前自动续期是必须的，手动续期迟早会忘
# 续期失败的排查方法，见本仓库的 [Let's Encrypt 证书自动续期失败排查](cert-renew-failed.md)
```

> 为什么证书要跟着域名结构走？因为证书和域名是一一对应的，域名结构改一次，证书就要跟着改一次。先定域名结构、再申请证书，顺序反了，等于每加一个子域名就要重新折腾一次证书。

## 验证清单：正式启用之前，这几项都要打勾

- [ ] 主域名续费价查过，按续费价算过长期成本，不是只看首年促销价
- [ ] 域名能顺口念出来，没有容易混淆的字符，连字符最多一个
- [ ] 面板、节点、订阅三个子域名已分开，职责和影响范围互不干扰
- [ ] 注册商开了隐私保护和双因素登录，域名到期提醒和自动续费已确认
- [ ] 解析商支持灵活的 TTL 和 API 操作，改解析的生效时间已实测过
- [ ] 域名解析用多个公共解析器查过，结果一致，没有旧解析残留
- [ ] 证书覆盖范围和子域名规划对得上，通配符证书的自动续期已配好
- [ ] 域名到期日已记进日历或监控，提前 30 天、7 天各有一次提醒

这几项都打勾，域名才算真正 ready；缺任何一项，都先补上再正式启用，否则以后补的成本只会更高。

## 常见坑汇总

- **只看首年价注册**：续费价翻几倍时，换域名的迁移成本远高于续费差价。
- **所有功能挤在一个域名上**：换节点、换订阅都要动全身，出错面大，改动也不敢做。
- **域名里混淆字符太多**：`l` 和 `1`、`o` 和 `0` 混用，用户手打输错一次就是一次投诉。
- **连字符用得太多**：口头传播说不清楚，别人拼不对，传播链就断了。
- **注册信息裸奔**：不开隐私保护，姓名、邮箱、电话全公开，骚扰和针对性攻击都会找上门。
- **域名账号没开双因素**：域名被盗等于整个机场的入口被改走，损失比服务器被黑还大。
- **TTL 设得太长**：平时没感觉，换节点、换 IP 时才发现用户要等很久才生效，故障时间被白白拉长。
- **域名过期没人管**：这是最不应该发生的事故，提前提醒和自动续费都要配好，缺一个都不行。
- **证书和域名结构脱节**：先申请证书、后改域名结构，每加一个子域名就要重新折腾证书。
- **接手有不良历史的域名**：前任用途留下的印象要花时间洗掉，不如一开始就选个干净的。
- **备用域名注册一堆**：平时用不上，续费和管理成本一年比一年高，等真需要时再加也不迟。
