# 面板机与节点端系统时间不同步导致节点认证失败：NTP 校时排查

面板和节点都在线、API 地址和密钥都没改过，节点却突然在面板上显示离线，或者订阅校验时断时续——这种时候先别急着重装节点端，也别先换密钥。很多类似的故障根源不在配置，而在时间：面板机和节点端两台机器的系统时间差得太多，带时间戳的认证、证书有效期校验就过不了，连接自然被拒绝。本文讲怎么确认是不是时间问题、怎么校时、校完怎么验证。示例中的域名、IP 均为占位符，请换成你自己的实际值。

## 时间差为什么会让节点认证失败

节点端向面板上报状态、拉取节点配置时，很多请求都依赖时间：有的用时间戳做签名防重放，有的用证书有效期做校验。面板收到一个时间戳明显超前或滞后的请求，会认为它过期或者不可信，直接拒绝；节点端校验面板下发的配置里证书的有效期时，如果本机时间跑偏，也会误判证书还没生效或者已经过期。于是表现出来的症状就很像网络问题或密钥问题：节点时在线时离线、订阅偶尔刷不出来、重启节点端能好一会儿、过一阵又不行。

时间漂移最常见的来源有三个：一是 VPS 刚开机、快照恢复或者宿主机时间本身就不准，系统时间从一开始就是错的；二是机器上根本没跑时间同步服务，时钟每天慢几秒、快几秒，攒上几周就差出好几分钟；三是面板机和节点端分别用了不同的时区设置，看起来时间显示不一样，实际上换算成 UTC 之后反而是一致的——这种情况不是故障，别把它当成时间差去修。动手之前先分清：到底是两台机器的 UTC 时间真的差了，还是只是时区显示不同。

## 第一步：先量出两台机器的时间差

不要凭感觉说“时间应该没问题”，先在面板机和节点端各跑一次，把 UTC 时间和本地时间都打印出来对比：

```bash
# 两台机器上都跑：同时看 UTC 时间、本地时间和时间同步状态
date -u
date
timedatectl status 2>/dev/null || chronyc tracking 2>/dev/null || ntpq -p 2>/dev/null
```

`date -u` 输出的是 UTC 时间，这是对比的基准——时区不同没关系，UTC 对不上才是真的差了。`timedatectl status` 里要看两行：`System clock synchronized` 是不是 `yes`，`NTP service` 是不是 `active`。如果同步状态是 `no` 或者服务根本没跑，说明这台机器的时间一直在自由漂移，迟早会出问题。

再看时间差到底有多大。几秒以内的偏差一般不至于让认证直接失败，几分钟以上的偏差就要高度怀疑；如果差了几个小时甚至几天，基本可以先锁定时间问题，再去查别的。下面这个办法可以直接在节点端测出它和面板机的时间差，不用两边来回翻终端：

```bash
# 在节点端：向面板机发一次请求，看响应头里的 Date，和本机时间对比
curl -sI https://panel.example.com 2>/dev/null | grep -i "^date:"
date -u
```

响应头里的 `Date` 是面板机按它自己的系统时间给出的，和节点端本机 UTC 时间一对比，差值就出来了。如果这一步发现两边差了好几分钟，就不用再怀疑密钥和网络了，先校时。

如果时间差不大、同步状态也正常，那就别在这个方向上耗着：回到节点离线的常规排查，看看是不是 API 地址、密钥或者防火墙的问题，可以对照本仓库的[V2bX 对接失败：面板显示节点离线怎么办](v2bx-offline-troubleshoot.md)按顺序往下查。

## 第二步：把两台机器都交给 NTP 同步

校时的正确做法不是手动把时间改对一次，而是让两台机器都持续跟 NTP 服务器同步。手动改时间只能管一时，时钟还会继续漂，下次故障只是时间问题。Debian、Ubuntu 这类系统上，优先用 `systemd-timesyncd` 或者 `chrony`，二选一，不要两个同时跑：

```bash
# 先确认当前用的是哪个同步服务，避免两个服务打架
systemctl status systemd-timesyncd chronyd ntp 2>/dev/null | grep -E "Active|Loaded"

# 方案一：用 systemd-timesyncd（大多数新系统默认就有）
timedatectl set-ntp true
systemctl enable --now systemd-timesyncd
timedatectl status
```

为什么是 `timedatectl set-ntp true`？这条命令是告诉系统启用网络时间同步，之后系统会自动找 NTP 服务器校时，不用你再手动干预。`enable --now` 则是既让服务现在就跑起来，又保证重启之后还会自动启动——只启动不设开机自启，机器一重启时间又会漂回去。

如果你的系统上装的是 `chrony`，就用 chrony 的方式，效果一样，不要两个混用：

```bash
# 方案二：用 chrony（适合时钟漂移比较大、或者需要更频繁校时的机器）
systemctl enable --now chronyd
chronyc tracking
chronyc sources -v
```

`chronyc tracking` 会告诉你当前时间离 NTP 服务器差多少、同步得稳不稳；`chronyc sources` 列出正在用的时间源。如果输出里所有时间源前面都带 `^?` 或者显示 unreachable，说明 NTP 请求根本没出去——先查防火墙有没有放行 UDP 123 端口，这是 NTP 走的端口，很多默认安全组规则会把它拦住。

## 第三步：强制校准一次，再确认差值归零

开启同步服务之后，系统通常会在几分钟内慢慢把时间追回来，但如果偏差已经很大，等它慢慢追太慢，可以先强制校准一次，再让服务接管后续的持续同步：

```bash
# 偏差很大时先强制同步一次：chrony 用 makestep，timesyncd 重启服务即可
chronyc makestep 2>/dev/null || systemctl restart systemd-timesyncd

# 等十几秒，再看一次同步状态和时间差
sleep 15
timedatectl status
date -u
```

强制校准只做一次就够了，做完之后不要再手动改时间——手动改时间和自动同步打架，反而会让同步服务反复调整，时间忽快忽慢。校准完成的标准是：面板机和节点端两边的 `date -u` 输出差值回到几秒以内，`timedatectl status` 里 `System clock synchronized` 显示为 `yes`。

校时完成之后，再回头验证业务是不是真的恢复了：重启节点端服务，让它重新向面板上报一次；到面板后台看节点是不是恢复在线；再用客户端拉一次订阅，确认能正常生成。顺序别反了——先校时、再重启节点端、最后看面板状态，重启早了、时间还没追回来，看到的还是离线，会误以为校时没用：

```bash
# 时间归零之后，再重启节点端服务，重新上报
systemctl restart v2bx 2>/dev/null || systemctl restart xray 2>/dev/null || docker restart v2bx
sleep 10
# 回到面板后台确认节点状态；再拉一次订阅验证
curl -s https://panel.example.com/api/subscription/你的订阅路径 -o /dev/null -w "%{http_code}\n"
```

如果节点恢复在线、订阅也能正常拉取，时间问题就到此为止了。顺手把这一步写进你的部署清单：以后每上一台新面板机或者新节点，第一件事就是确认 NTP 服务在跑、同步状态是 `yes`，而不是等出故障了再来查时间。

## 常见坑汇总

- **只改了时区，没改时间**：`timedatectl set-timezone` 改的只是显示用的时区，UTC 时间本身没变。两台机器时区不同是正常的，对比一定要用 `date -u`，不要看本地时间。
- **手动改完时间就以为修好了**：没有同步服务兜底，时钟还会继续漂，几天或者几周后故障会重现。手动改时间只是应急，长期方案一定是 NTP。
- **两个同步服务同时跑**：`systemd-timesyncd` 和 `chrony` 或者 `ntpd` 一起启用会互相干扰，时间反而跳来跳去。留一个，停掉并禁用其他的。
- **防火墙拦了 UDP 123**：NTP 服务启动了，但时间源全部 unreachable，时间永远同步不上。先放行出方向的 UDP 123，再查时间源。
- **只校了面板机，没校节点端**：认证是两边时间对比，任何一边偏了都会失败。面板机和节点端要两边都查、两边都校，只校一边等于没校。
- **快照恢复后没检查时间**：从快照恢复的机器，系统时间可能停留在快照那一刻，差出几天都有可能。恢复完第一件事就是看 `date -u` 和同步状态。
- **证书报错就以为是证书问题**：证书还没生效或者已经过期的报错，有一半是本机时间跑偏造成的假象。换证书之前先看一眼时间，几分钟就能排除一个大方向。

节点离线、订阅校验失败这类故障，查到最后发现是时间问题的情况并不少见，偏偏它又最容易被忽略：配置、密钥、网络都查了一圈，最后才想起两台机器的时间根本没对过。以后遇到类似症状，先花一分钟跑 `date -u` 和 `timedatectl status`，确认时间没问题再往配置方向查，能省下不少绕圈子的时间。
